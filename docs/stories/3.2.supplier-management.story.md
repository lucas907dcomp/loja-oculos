## Story

**As a** store owner,
**I want** to register suppliers with their contact information and lead time, view which products are associated with each supplier, and register purchase orders with their delivery status,
**so that** I can track my procurement relationships, understand lead times for reordering, and have a history of all purchase orders per supplier (spec.md Section 3.4, FR-7, AC-7.1 – AC-7.3).

## Acceptance Criteria

1. **Schema migration** — two additions to the database schema:
   - Add `phone String?` and `email String?` fields to the existing `Supplier` model (DM-8 completeness)
   - Create new `PurchaseOrder` model: `{ id: String @cuid; supplierId: String; supplier: Supplier; status: PurchaseOrderStatus @default(REQUESTED); notes: String?; deliveredAt: DateTime?; createdAt: DateTime @default(now()); updatedAt: DateTime @updatedAt }` with enum `PurchaseOrderStatus { REQUESTED DELIVERED }`
   - Add `purchaseOrders PurchaseOrder[]` relation to `Supplier` model
   - Run `npx prisma migrate dev --name add-supplier-phone-email-purchase-orders`
   - (FR-7, DM-8)

2. `src/features/suppliers/supplier.contract.ts` — exports public types:
   - `SupplierRecord`: `{ id: string; name: string; cnpj: string | null; contactName: string | null; phone: string | null; email: string | null; leadTimeDays: number; createdAt: Date; updatedAt: Date }`
   - `SupplierSummary`: `{ id: string; name: string; cnpj: string | null; contactName: string | null; phone: string | null; email: string | null; leadTimeDays: number; productCount: number; createdAt: Date }`
   - `PurchaseOrderRecord`: `{ id: string; supplierId: string; status: 'REQUESTED' | 'DELIVERED'; notes: string | null; deliveredAt: Date | null; createdAt: Date }`
   - `SupplierWithDetails`: extends `SupplierRecord` with `products: { id: string; name: string; brand: string; variantCount: number }[]` and `purchaseOrders: PurchaseOrderRecord[]`
   - `CreateSupplierDTO`: `{ name: string; cnpj?: string; contactName?: string; phone?: string; email?: string; leadTimeDays?: number }`
   - `UpdateSupplierDTO`: all fields optional from `CreateSupplierDTO`
   - `CreatePurchaseOrderDTO`: `{ notes?: string }`
   - All types barrel-exported from `src/features/suppliers/index.ts`
   - (FR-7)

3. `src/features/suppliers/services/supplier.service.ts` — `SupplierService` class (static pattern):
   - `getSuppliers(search?: string): Promise<SupplierSummary[]>` — returns all suppliers with product count; optionally filters by name/CNPJ/contactName (case-insensitive `contains`); ordered by `name ASC`
   - `getSupplierById(id: string): Promise<SupplierWithDetails>` — returns supplier with product list (id, name, brand, variant count) and full purchase orders history (ordered by `createdAt DESC`); throws `Error('Fornecedor não encontrado')` if not found
   - `createSupplier(dto: CreateSupplierDTO): Promise<SupplierRecord>` — validates `dto.name` non-empty (throws `Error('Nome obrigatório')`); `leadTimeDays` defaults to `7` if not provided
   - `updateSupplier(id: string, dto: UpdateSupplierDTO): Promise<SupplierRecord>` — validates supplier exists before update (throws `Error('Fornecedor não encontrado')`); patches only provided fields
   - `createPurchaseOrder(supplierId: string, dto: CreatePurchaseOrderDTO): Promise<PurchaseOrderRecord>` — validates supplier exists (throws `Error('Fornecedor não encontrado')`); creates PO with status `REQUESTED`
   - `updatePurchaseOrderStatus(id: string, status: 'REQUESTED' | 'DELIVERED'): Promise<PurchaseOrderRecord>` — validates PO exists (throws `Error('Pedido não encontrado')`); if status → `DELIVERED`, sets `deliveredAt = new Date()`; if status → `REQUESTED`, clears `deliveredAt = null`
   - (FR-7 AC-7.1, AC-7.3)

4. `src/features/suppliers/actions.ts` — Server Actions (`'use server'`):
   - `getSuppliersAction(search?)` — calls `SupplierService.getSuppliers(search)`, maps `createdAt` to ISO string
   - `getSupplierByIdAction(id)` — calls `SupplierService.getSupplierById(id)`, maps all Date fields to ISO strings
   - `createSupplierAction(dto)` — calls `SupplierService.createSupplier(dto)`; on success `revalidatePath('/fornecedores')`; returns `{ success: true; id: string }` or `{ success: false; error: string }`

### SupplierService — Pattern Reference

[Source: src/features/customers/services/customer.service.ts — static class pattern, Story 3.1]

```typescript
// src/features/suppliers/services/supplier.service.ts
import { prisma } from '@/lib/prisma'
import type { SupplierRecord, SupplierSummary, CreateSupplierDTO, UpdateSupplierDTO, CreatePurchaseOrderDTO, PurchaseOrderRecord } from '../supplier.contract'

export class SupplierService {
  static async getSuppliers(search?: string): Promise<SupplierSummary[]> {
    const suppliers = await prisma.supplier.findMany({
      where: search ? {
        OR: [
          { name: { contains: search, mode: 'insensitive' } },
          { cnpj: { contains: search, mode: 'insensitive' } },
          { contactName: { contains: search, mode: 'insensitive' } },
        ],
      } : undefined,
      include: {
        _count: { select: { products: true } },
      },
      orderBy: { name: 'asc' },
    })
    return suppliers.map((s) => ({ ...s, productCount: s._count.products }))
  }

  static async getSupplierById(id: string): Promise<SupplierWithDetails> {
    const supplier = await prisma.supplier.findUnique({
      where: { id },
      include: {
        products: {
          select: { id: true, name: true, brand: true, _count: { select: { variants: true } } },
          where: { isArchived: false },
          orderBy: { name: 'asc' },
        },
        purchaseOrders: {
          orderBy: { createdAt: 'desc' },
        },
      },
    })
    if (!supplier) throw new Error('Fornecedor não encontrado')
    return {
      ...supplier,
      products: supplier.products.map((p) => ({ ...p, variantCount: p._count.variants })),
    }
  }

  static async createSupplier(dto: CreateSupplierDTO): Promise<SupplierRecord> {
    if (!dto.name?.trim()) throw new Error('Nome obrigatório')
    return prisma.supplier.create({
      data: {
        name: dto.name.trim(),
        cnpj: dto.cnpj?.trim() || null,
        contactName: dto.contactName?.trim() || null,
        phone: dto.phone?.trim() || null,
        email: dto.email?.trim() || null,
        leadTimeDays: dto.leadTimeDays ?? 7,
      },
    })
  }

  static async updatePurchaseOrderStatus(id: string, status: 'REQUESTED' | 'DELIVERED'): Promise<PurchaseOrderRecord> {
    const existing = await prisma.purchaseOrder.findUnique({ where: { id } })
    if (!existing) throw new Error('Pedido não encontrado')
    return prisma.purchaseOrder.update({
      where: { id },
      data: {
        status,
        deliveredAt: status === 'DELIVERED' ? new Date() : null,
      },
    })
  }
}
```

**CRITICAL:** `getSuppliers` uses `_count: { select: { products: true } }` to avoid N+1. Never count products in a loop.

### CRITICAL — Four Independent `useTransition` Hooks in fornecedores-client.tsx

[Source: @po S-1 fix — same pattern as Story 3.1 @po S-1 for pdv-client.tsx dual transitions]

The `FornecedoresClient` manages four distinct async operations, each with independent pending state:

```typescript
const [isPending, startTransition] = useTransition()          // create supplier form submit
const [isLoadingProfile, startProfileTransition] = useTransition() // getSupplierByIdAction
const [isMarkingDelivered, startDeliverTransition] = useTransition() // updatePurchaseOrderStatus
const [isCreatingPO, startPOTransition] = useTransition()     // createPurchaseOrderAction
```

**NEVER** reuse the create supplier `startTransition` for profile or PO operations — `isPending` gates the "Cadastrar" button, and sharing would incorrectly disable the create form while a PO action runs.

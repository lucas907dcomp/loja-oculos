## Story

**As a** cliente da Vitrine que revisou seu carrinho,
**I want** preencher meus dados de contato e gerar um link WhatsApp para finalizar minha compra,
**so that** posso contatar a loja com os detalhes do pedido sem precisar de gateway de pagamento (spec.md FR-16, CON-7, CON-8, Epic 5 — Headless E-commerce Vitrine).

## Acceptance Criteria

1. **Página de Checkout** — `src/app/(storefront)/loja/checkout/page.tsx` (`'use client'`):
   - Lê `items` e `clearCart` de `useCartStore`
   - Se `items.length === 0` → exibe estado vazio com link "Voltar para a loja" (`/loja/produtos`) — sem redirect automático
   - Renderiza formulário com: nome (required, min 2 chars), telefone (required, min 8 chars), e-mail (opcional)
   - Validação client-side com React Hook Form + Zod
   - Exibe resumo do carrinho (readonly): lista de itens e total
   - Botão "Finalizar Pedido via WhatsApp" — ao submeter: chama Server Action `createCustomer()`; em caso de sucesso gera link WhatsApp → abre em `window.open(url, '_blank')` → chama `clearCart()` → exibe confirmação "Pedido enviado!"
   - Em caso de erro da action → exibe mensagem de erro inline (sem redirect)
   - (FR-16, CON-7, CON-8)

2. **Server Action** — `src/app/(storefront)/loja/checkout/actions.ts`:
   - Diretiva `'use server'` no topo do arquivo
   - `export async function createCustomer(data: { name: string; phone: string; email?: string })` — Server Action
   - Valida payload server-side com Zod (`CustomerSchema`): `name` min 2, `phone` min 8, `email` opcional
   - Persiste via `prisma.customer.create()` — acesso direto ao banco, sem HTTP para `/api/v1/`; CON-7 garantido (sem `ECOMMERCE_API_KEY` no client)
   - Retorna `{ id: string }` em sucesso ou `{ error: string }` em falha
   - (FR-16, CON-7)

3. **WhatsApp Link** — gerado client-side após Server Action bem-sucedida:
   - Número de destino: `process.env.NEXT_PUBLIC_STOREFRONT_WHATSAPP_PHONE` (fallback: `'5511999999999'`)
   - Mensagem pré-formatada com: saudação, lista de itens (`productName + variantLabel + qty + preço unitário`), total, nome do cliente, telefone do cliente
   - Formato: `https://wa.me/{phone}?text={encodeURIComponent(message)}`
   - Aberto via `window.open(url, '_blank')`
   - Após abertura: `clearCart()` e UI transiciona para estado de confirmação
   - (FR-16, CON-8)

4. **Variável de ambiente** — `NEXT_PUBLIC_STOREFRONT_WHATSAPP_PHONE`:
   - Adicionar ao `.env.local.example` com comentário explicativo
   - Valor de exemplo: `5511999999999` (formato internacional sem `+`)
   - Não é variável secreta — é o número público de WhatsApp da loja
   - (FR-16)

5. **Testes unitários** — `src/features/storefront/__tests__/checkout.test.tsx`:
   - Mock: `vi.mock('@/store/cart', () => ({ useCartStore: vi.fn() }))` — mesmo padrão de Story 5.3
   - Mock do Server Action: `vi.mock('../../../app/(storefront)/loja/checkout/actions')`
   - **Casos obrigatórios:**
     - Exibe estado vazio quando `items = []`
     - Renderiza resumo do carrinho com itens quando `items` tem entradas
     - Botão de submit está desabilitado enquanto nome ou telefone estão em branco
     - Submit com dados válidos chama `createCustomer()` com `{ name, phone, email }`
     - Após sucesso da action: chama `clearCart()` e exibe confirmação
     - Após erro da action: exibe mensagem de erro sem chamar `clearCart()`
     - `window.open` chamado com URL de WhatsApp contendo itens do carrinho após sucesso
   - (FR-16)

6. **Typecheck + lint** — `npx tsc --noEmit` e `npm run lint` passam com zero erros; `ECOMMERCE_API_KEY` e `process.env` server-only ausentes em todos os arquivos `'use client'`; `NEXT_PUBLIC_STOREFRONT_WHATSAPP_PHONE` é a única variável pública adicionada
   - (CON-7)

### Server Action Pattern (Next.js App Router)

```typescript
// src/app/(storefront)/loja/checkout/actions.ts
'use server'

import { z } from 'zod'
import { prisma } from '@/lib/prisma'

const CustomerSchema = z.object({
  name: z.string().min(2, 'Nome obrigatório'),
  phone: z.string().min(8, 'Telefone obrigatório'),
  email: z.string().email().optional().or(z.literal('')),
})

export async function createCustomer(data: {
  name: string
  phone: string
  email?: string
}): Promise<{ id: string } | { error: string }> {
  const parsed = CustomerSchema.safeParse(data)
  if (!parsed.success) {
    return { error: parsed.error.errors[0]?.message ?? 'Dados inválidos' }
  }
  try {
    const customer = await prisma.customer.create({
      data: {
        name: parsed.data.name,
        phone: parsed.data.phone,
        email: parsed.data.email || null,
        tags: [],
      },
    })
    return { id: customer.id }
  } catch {
    return { error: 'Erro ao salvar dados. Tente novamente.' }
  }
}
```

**CON-7 compliance:** `actions.ts` tem `'use server'` — nunca é `'use client'`; `prisma` importado apenas em arquivos server-only; `ECOMMERCE_API_KEY` não é necessário neste fluxo (acesso direto ao banco via Prisma).

### WhatsApp Link Generation (Client-side)

```typescript
function buildWhatsAppLink(items: CartItem[], customerName: string, phone: string): string {
  const storePhone = process.env.NEXT_PUBLIC_STOREFRONT_WHATSAPP_PHONE ?? '5511999999999'
  const lines = items.map(
    (i) => `• ${i.productName} (${i.variantLabel}) x${i.quantity} — ${formatPrice(i.price)}`
  )
  const total = parseFloat(
    items.reduce((s, i) => s + parseFloat(i.price) * i.quantity, 0).toFixed(2)
  ).toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' })
  const message = [
    'Olá! Gostaria de fazer o seguinte pedido:',
    '',
    ...lines,
    '',
    `Total: ${total}`,
    '',
    `Nome: ${customerName}`,
    `Telefone: ${phone}`,
  ].join('\n')
  return `https://wa.me/${storePhone}?text=${encodeURIComponent(message)}`
}
```

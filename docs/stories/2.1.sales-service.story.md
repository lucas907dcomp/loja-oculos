## Story

**As a** store owner,
**I want** the system to record a sale atomically — decrementing stock per variant, snapshotting prices, generating an audit trail, and creating the cash flow entry — all in a single database transaction,
**so that** data is always consistent even in case of partial failure, and the PDV can rely on one service call to complete a sale safely (spec.md Section 3.3, FR-3, FR-5, NFR-3).

## Acceptance Criteria

1. `src/features/sales/sales.contract.ts` exports `PaymentBreakdown`, `CreateSaleItemDTO`, `CreateSaleDTO`, `SaleWithItems`, `SaleListItem`; all barrel-exported from `src/features/sales/index.ts`. `PaymentBreakdown` uses optional `number` fields (`pix?`, `cardCredit?`, `cardDebit?`, `cash?`; all ≥ 0). Returned monetary fields (`totalAmount`, `unitPrice`, `unitCost`) are typed as `Decimal` from `decimal.js`. No Decimal fields on input DTOs — UI submits plain numbers. (FR-3, FR-4, FR-5)

2. `SalesService.createSale(dto: CreateSaleDTO)` — the critical atomic operation [spec.md Section 3.3, NFR-3, EC-1]:
   - Validates `dto.items.length >= 1`; throws `Error('Carrinho não pode estar vazio')`
   - Validates each `item.quantity >= 1`; throws `Error('Quantidade inválida')`
   - **Pre-transaction EC-1 check** (blocking): fetches each variant's `Inventory`; if any `inventory.quantity < item.quantity`, throws `Error('Estoque insuficiente para {productName} — {sku}')` before `$transaction` is opened — no partial DB state
   - Computes `totalAmount` server-side: `Σ item.quantity × variant.salePrice` (Decimal.js arithmetic); never trusts client-supplied total
   - Validates payment coverage: `Σ paymentBreakdown values === totalAmount` (Decimal equality); throws `Error('Total do pagamento não cobre o valor da venda')` if mismatch
   - Inside `prisma.$transaction(async (tx) => { ... })`:
     a. Creates `Sale` with `totalAmount`, `paymentBreakdown` (as `Prisma.InputJsonValue`), optional `customerId`, `status: COMPLETED`
     b. For each item: creates `SaleItem` with `saleId`, `variantId`, `quantity`, `unitPrice: variant.salePrice` (snapshot), `unitCost: variant.costPrice` (snapshot)
     c. For each item: decrements `Inventory.quantity` via `{ quantity: { decrement: item.quantity } }`
     d. For each item: creates `InventoryTransaction` with `type: SALE`, `quantityDelta: -item.quantity`, `inventoryId`
     e. Creates `CashFlowEntry` with `type: INCOME`, `amount: totalAmount`, `saleId: sale.id`
   - Returns the created `SaleWithItems`

3. `SalesService.getSaleHistory(filters?: { from?: Date; to?: Date })` — returns `SaleListItem[]` ordered by `createdAt DESC`; applies optional date range on `createdAt`; includes `itemCount` and `customerName` (if sale has customer). (FR-3)

4. `SalesService.getSaleById(id: string)` — returns `SaleWithItems` including `items` (each with `variant: { sku, frameColor, lensColor, product: { name } }`), `customer`, and `cashFlowEntry`; throws `Error('Venda não encontrada')` if not found. (FR-3)

5. `src/features/sales/actions.ts` exports Server Actions (`'use server'`):
   - `createSaleAction(dto: CreateSaleDTO)` — calls `SalesService.createSale()`; on success: `revalidatePath('/vendas')` and `revalidatePath('/estoque')`; returns `{ success: true, saleId: string }` or `{ success: false, error: string }`. (FR-3, FR-5)

6. Unit tests in `src/features/sales/__tests__/sales.service.test.ts` (≥ 90% service coverage):
   - `createSale()` happy path — 1 item, Pix = totalAmount: `$transaction` called once; `SaleItem` created with correct unitPrice/unitCost snapshots; `Inventory.quantity` decremented; `InventoryTransaction(SALE, -qty)` created; `CashFlowEntry(INCOME)` created with totalAmount
   - `createSale()` multi-item — 2 different variants: both inventories decremented, both InventoryTransactions created, CashFlowEntry amount = sum of both items
   - `createSale()` stock insufficient — throws `'Estoque insuficiente...'` AND `$transaction` NOT called
   - `createSale()` split payment (Pix + Cash) — `paymentBreakdown` stored with both values; sale created normally
   - `createSale()` empty cart — throws `'Carrinho não pode estar vazio'`
   - `createSale()` payment mismatch — throws `'Total do pagamento não cobre...'`
   - `getSaleById()` — non-existent ID throws error
   - `getSaleHistory()` — returns array (mocked) ordered DESC

### createSale Atomic Pattern
[Source: spec.md#section-3-3 — Operação Crítica; NFR-3; EC-1; FR-3 AC-3.4; FR-5 AC-5.1]

```typescript
// src/features/sales/services/sales.service.ts
import Decimal from 'decimal.js'
import { prisma } from '@/lib/prisma'
import type { CreateSaleDTO, SaleWithItems } from '../sales.contract'

async createSale(dto: CreateSaleDTO): Promise<SaleWithItems> {
  // --- Validation ---
  if (!dto.items.length) throw new Error('Carrinho não pode estar vazio')
  for (const item of dto.items) {
    if (item.quantity < 1) throw new Error('Quantidade inválida')
  }

  // --- Pre-transaction fetch (variants + inventories) ---
  const variantData = await Promise.all(
    dto.items.map(item =>
      prisma.productVariant.findUniqueOrThrow({
        where: { id: item.variantId },
        include: { product: { select: { name: true } }, inventory: true }
      })
    )
  )

  // --- EC-1: stock check BEFORE opening transaction ---
  for (let i = 0; i < dto.items.length; i++) {
    const inv = variantData[i].inventory
    if (!inv || inv.quantity < dto.items[i].quantity) {
      throw new Error(`Estoque insuficiente para ${variantData[i].product.name} — ${variantData[i].sku}`)
    }
  }

  // --- Compute totalAmount (server-side, Decimal.js) ---
  const totalAmount = variantData.reduce((sum, v, i) =>
    sum.plus(new Decimal(dto.items[i].quantity).mul(v.salePrice.toString())),
    new Decimal(0)
  )

  // --- Payment sum validation ---
  const paymentSum = new Decimal(dto.paymentBreakdown.pix ?? 0)
    .plus(dto.paymentBreakdown.cardCredit ?? 0)
    .plus(dto.paymentBreakdown.cardDebit ?? 0)
    .plus(dto.paymentBreakdown.cash ?? 0)
  if (!paymentSum.equals(totalAmount)) {
    throw new Error('Total do pagamento não cobre o valor da venda')
  }

  // --- Atomic transaction ---
  return prisma.$transaction(async (tx) => {
    // Step a: Create Sale
    const sale = await tx.sale.create({
      data: {
        totalAmount: totalAmount.toFixed(2),
        paymentBreakdown: dto.paymentBreakdown as Prisma.InputJsonValue,
        customerId: dto.customerId ?? null,
        status: 'COMPLETED',
      }
    })

    for (let i = 0; i < dto.items.length; i++) {
      const item = dto.items[i]
      const variant = variantData[i]
      const inv = variant.inventory!

      // Step b: SaleItem (price snapshots)
      await tx.saleItem.create({
        data: {
          saleId: sale.id,
          variantId: item.variantId,
          quantity: item.quantity,
          unitPrice: variant.salePrice.toString(),
          unitCost: variant.costPrice.toString(),
        }
      })

      // Step c: Decrement inventory
      await tx.inventory.update({
        where: { id: inv.id },
        data: { quantity: { decrement: item.quantity } }
      })

      // Step d: InventoryTransaction (SALE, negative delta)
      await tx.inventoryTransaction.create({
        data: {
          inventoryId: inv.id,
          type: 'SALE',
          quantityDelta: -item.quantity,  // MUST be negative for SALE
          note: null,
        }
      })
    }

    // Step e: CashFlowEntry (INCOME, linked to sale)
    await tx.cashFlowEntry.create({
      data: {
        type: 'INCOME',
        amount: totalAmount.toFixed(2),
        saleId: sale.id,
      }
    })

    // Return full SaleWithItems
    return tx.sale.findUniqueOrThrow({
      where: { id: sale.id },
      include: {
        items: { include: { variant: { include: { product: { select: { name: true } } } } } },
        customer: true,
        cashFlowEntry: true,
      }
    })
  })
}
```

**Critical:** `InventoryTransaction.quantityDelta` is **`-item.quantity`** (negative) for SALE type.
**Critical:** `unitPrice` and `unitCost` are snapshots — use `variant.salePrice.toString()` and `variant.costPrice.toString()` to pass Decimal values to Prisma.

### getSaleHistory Query Pattern
[Source: spec.md#section-5-3 — vendas/page.tsx; FR-3 AC-3]

```typescript
static async getSaleHistory(filters?: { from?: Date; to?: Date }): Promise<SaleListItem[]> {
  const where = filters ? {
    createdAt: {
      gte: filters.from,
      lte: filters.to,
    }
  } : {}

  const sales = await prisma.sale.findMany({
    where,
    orderBy: { createdAt: 'desc' },
    include: {
      customer: { select: { name: true } },
      _count: { select: { items: true } },
    }
  })

  return sales.map(s => ({
    id: s.id,
    totalAmount: s.totalAmount,
    status: s.status,
    createdAt: s.createdAt,
    itemCount: s._count.items,
    customerName: s.customer?.name ?? null,
  }))
}
```

### Decimal Handling in Tests
[Source: Story 1.4 test pattern; spec.md Section 3.1 — Decimal.js requirement]

Prisma returns `Decimal` objects for `@db.Decimal(10,2)` fields. When mocking, return objects with `.toString()` method or use Decimal instances:

```typescript
// In test mock:
salePrice: { toString: () => '120.00' },
costPrice: { toString: () => '50.00' },
// OR:
import Decimal from 'decimal.js'
salePrice: new Decimal('120.00'),
```

The service uses `new Decimal(value.toString())` when calling `.mul()` to handle both forms safely.

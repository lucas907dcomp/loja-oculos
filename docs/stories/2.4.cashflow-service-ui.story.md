## Story

**As a** store owner,
**I want** to see all cash flow entries (sales income, return expenses, and manually-entered operational costs) with daily/monthly summaries and a way to add manual expense entries,
**so that** I can track the daily financial health of the store and understand whether I'm operating at a profit or loss each day and month (spec.md Section 3.2, FR-5, AC-5.2, AC-5.3, AC-5.4).

## Acceptance Criteria

1. `src/features/cashflow/cashflow.contract.ts` — exports public types:
   - `CashFlowEntryRecord`: `{ id: string; type: 'INCOME' | 'EXPENSE'; amount: Decimal; note: string | null; date: Date; saleId: string | null }`
   - `CashFlowSummary`: `{ income: Decimal; expense: Decimal; balance: Decimal }` (balance = income − expense)
   - `CreateManualEntryDTO`: `{ type: 'INCOME' | 'EXPENSE'; amount: number; note: string; date?: Date }`
   - All types barrel-exported from `src/features/cashflow/index.ts`
   - (FR-5)

2. `src/features/cashflow/services/cashflow.service.ts` — `CashFlowService` class:
   - `getEntries(filters?: { from?: Date; to?: Date; type?: 'INCOME' | 'EXPENSE' }): Promise<CashFlowEntryRecord[]>` — returns all entries in date range ordered by `date DESC`; no filters = current month
   - `getMonthlySummary(year: number, month: number): Promise<CashFlowSummary>` — aggregates INCOME and EXPENSE for the given month; balance = income − expense (Decimal arithmetic)
   - `createManualEntry(dto: CreateManualEntryDTO): Promise<CashFlowEntryRecord>` — validates `dto.amount > 0` (throws `Error('Valor inválido')`); validates `dto.note` non-empty (throws `Error('Descrição obrigatória')`); creates `CashFlowEntry` with `saleId: null`
   - No `$transaction` required — each operation is a single Prisma write
   - (FR-5 AC-5.2, AC-5.3, AC-5.4)

3. `src/features/cashflow/actions.ts` — Server Actions (`'use server'`):
   - `getCashFlowEntriesAction(filters?)`: calls `CashFlowService.getEntries(filters)`, returns serializable DTO (amount as string)
   - `getMonthlySummaryAction(year, month)`: returns `{ income: string; expense: string; balance: string }` or `{ success: false; error: string }`
   - `createManualEntryAction(dto)`: calls `CashFlowService.createManualEntry(dto)`; on success: `revalidatePath('/financeiro')`; returns `{ success: true }` or `{ success: false; error: string }` (never throws)
   - (FR-5)

4. `app/(backoffice)/financeiro/page.tsx` — Server Component (replaces placeholder):
   - Defaults to current month; calls `CashFlowService.getEntries()` and `CashFlowService.getMonthlySummary(year, month)` in parallel (Promise.all)
   - On error: renders fallback `<p className="text-destructive">Erro ao carregar fluxo de caixa.</p>`
   - Renders `<FinanceiroClient entries={entries} summary={summary} year={year} month={month} />`
   - No `'use client'` directive
   - (FR-5 AC-5.3, AC-5.4)

5. `app/(backoffice)/financeiro/financeiro-client.tsx` — Client Component (`'use client'`):
   - Receives `entries: CashFlowEntryRecord[]`, `summary: CashFlowSummary`, `year: number`, `month: number` as serializable props (amounts as strings)
   - **Summary cards** (top of page): three cards — "Entradas" (green), "Saídas" (red), "Saldo" (green if ≥ 0, red if < 0); each shows formatted BRL value
   - **Entries table**: columns — Date, Type badge (INCOME → `outline`, EXPENSE → `destructive`), Description (note or "Venda" if saleId present, or "Devolução" if related), Amount (BRL)
   - **Empty state**: "Nenhum lançamento no período." (no crash)
   - **"+ Lançamento Manual" button**: opens a Sheet with a form (type selector: Receita/Despesa, amount input, description input, optional date); on submit calls `createManualEntryAction`; on success closes sheet and shows 5-second success message; on error shows inside sheet
   - Uses `useTransition` for `isPending` during manual entry submission
   - (FR-5 AC-5.2, AC-5.3, AC-5.4)

6. Unit tests in `src/features/cashflow/__tests__/cashflow.service.test.ts` (new file):

   - `getMonthlySummary` — empty month: income=0, expense=0, balance=0

### Prisma Schema — CashFlowEntry (DM-9)

```prisma
model CashFlowEntry {
  id        String        @id @default(cuid())
  type      CashFlowType                        // INCOME | EXPENSE
  amount    Decimal       @db.Decimal(10, 2)
  note      String?
  date      DateTime      @default(now())
```

**Key point:** `saleId` is `@unique` — one `CashFlowEntry` per `Sale` at most. Manual entries have `saleId: null`.

### CashFlowService — Decimal Aggregation Pattern
[Source: spec.md#section-6.1 — `CashFlowService.getDailySummary` test requirement; FR-5 AC-5.3]

```typescript
// src/features/cashflow/services/cashflow.service.ts
import Decimal from 'decimal.js'
import { prisma } from '@/lib/prisma'

export class CashFlowService {
  static async getMonthlySummary(year: number, month: number): Promise<CashFlowSummary> {
    const from = new Date(year, month - 1, 1)       // first day of month
    const to   = new Date(year, month, 0, 23, 59, 59, 999)  // last ms of month

    const entries = await prisma.cashFlowEntry.findMany({
      where: { date: { gte: from, lte: to } },
      select: { type: true, amount: true },
    })

    let income  = new Decimal(0)
    let expense = new Decimal(0)

    for (const entry of entries) {
      const amount = new Decimal(entry.amount.toString())
      if (entry.type === 'INCOME')  income  = income.plus(amount)
      else                          expense = expense.plus(amount)
    }

    return { income, expense, balance: income.minus(expense) }
  }
}
```

**CRITICAL:** Never use `Number()` or native JS `+` to aggregate monetary values — use `Decimal.plus()`. *(FR-4 rationale, spec.md#3.1)*

### getEntries Default Filter — Current Month
[Source: spec.md#section-5.3 — financeiro/page.tsx purpose: "Fluxo de caixa + visão semanal/mensal"]

`getEntries()` without filters defaults to the current calendar month to avoid unbounded queries as data grows. The RSC page computes `year = now.getFullYear()` and `month = now.getMonth() + 1` and passes them to the service.

### createManualEntry — Validation Pattern
[Source: FR-5 AC-5.2 + established pattern from sales.service.ts:8-11]

Input validation occurs BEFORE any Prisma call — matches the guard pattern in `createSale`:

```typescript
static async createManualEntry(dto: CreateManualEntryDTO): Promise<CashFlowEntryRecord> {
  if (dto.amount <= 0) throw new Error('Valor inválido')
  if (!dto.note?.trim()) throw new Error('Descrição obrigatória')

  const entry = await prisma.cashFlowEntry.create({
    data: {
      type:   dto.type,
      amount: new Decimal(dto.amount).toFixed(2),
      note:   dto.note.trim(),
      date:   dto.date ?? new Date(),
      saleId: null,
    },
  })
  return entry as CashFlowEntryRecord
}
```

### Server + Client Component Split
[Source: spec.md#section-5.3 + Story 2.3 pattern]

```typescript
// app/(backoffice)/financeiro/page.tsx — Server Component (replaces placeholder)
import { CashFlowService } from '@/features/cashflow'
import { FinanceiroClient } from './financeiro-client'

export default async function FinanceiroPage() {
  const now   = new Date()
  const year  = now.getFullYear()
  const month = now.getMonth() + 1

  let entries, summary
  try {
    ;[entries, summary] = await Promise.all([
      CashFlowService.getEntries({ from: new Date(year, month - 1, 1) }),
      CashFlowService.getMonthlySummary(year, month),
    ])
  } catch {
    return (
      <div className="flex flex-col items-center justify-center h-64 gap-3">
        <p className="text-destructive font-medium">Erro ao carregar fluxo de caixa.</p>
        <p className="text-muted-foreground text-sm">Verifique a conexão e recarregue a página.</p>
      </div>
    )
  }
  return <FinanceiroClient entries={entries} summary={summary} year={year} month={month} />
}
```

### Saldo Color Logic
[Source: FR-5 AC-5.3 — "Saldo diário calculado: entradas - saídas"]

Balance card color: green (`text-green-700`) when balance ≥ 0, red (`text-destructive`) when balance < 0. Both states must be handled — a store can have a net-negative day (refunds exceed sales).

**CRITICAL (serialization):** Next.js RSC serializes `Prisma.Decimal` via `.toJSON()` → the Client Component receives `summary.balance` as a **string**, not a Decimal instance. Calling `.gte()` directly on the received value will throw at runtime. Always wrap before comparing:

```typescript
const bal = new Decimal(summary.balance.toString())
const isNegative = bal.lt(0)
// then use isNegative to toggle className
```

Same applies to `summary.income` and `summary.expense` — use `new Decimal(value.toString())` before any arithmetic.

## Story

**As a** store owner,
**I want** a printable sale receipt to appear automatically after each sale is confirmed in the PDV,
**so that** I can hand a physical or on-screen voucher to the customer and keep a visual record of the transaction (spec.md FR-3, AC-3.5).

## Acceptance Criteria

1. **No schema migration required** — receipt data is derived from the existing `Sale`, `SaleItem`, `ProductVariant`, and `Customer` models; no new tables or columns needed.
   - (FR-3 AC-3.5)

2. **Receipt contract** — `src/features/sales/receipt.contract.ts` exports:
   - `ReceiptItem`: `{ sku: string; productName: string; frameColor: string; lensColor: string; quantity: number; unitPrice: string; subtotal: string }`
   - `ReceiptData`: `{ saleId: string; shortId: string; createdAt: string; customerName: string | null; items: ReceiptItem[]; totalAmount: string; paymentBreakdown: PaymentBreakdown; itemCount: number }`
     - `shortId`: last 8 chars of `saleId` uppercased (e.g. `"ABC12345"`)
     - `createdAt`: ISO 8601 string (serializable across Server→Client boundary)
     - `totalAmount` and `unitPrice` and `subtotal`: decimal strings (e.g. `"199.90"`)
   - Exported from the existing `src/features/sales/index.ts` barrel (`export type { ReceiptData, ReceiptItem }`)
   - (FR-3 AC-3.5)

3. **`buildReceipt` helper** — `src/features/sales/receipt.contract.ts` also exports:
   - `buildReceipt(sale: SaleWithItems): ReceiptData` — pure function (no Prisma), converts a `SaleWithItems` to `ReceiptData`
     - Maps each `SaleItem` to `ReceiptItem`; `subtotal = (unitPrice × quantity).toFixed(2)` using `decimal.js`
     - `shortId = sale.id.slice(-8).toUpperCase()`
     - `createdAt = sale.createdAt.toISOString()`
     - `customerName = sale.customer?.name ?? null`
   - (FR-3 AC-3.5)

4. **`getSaleForReceiptAction`** — add to `src/features/sales/actions.ts`:
   - `getSaleForReceiptAction(saleId: string): Promise<{ success: true; receipt: ReceiptData } | { success: false; error: string }>`
   - Calls `SalesService.getSaleById(saleId)` and applies `buildReceipt(sale)`
   - (FR-3 AC-3.5)

5. **`<SaleReceipt />` component** — new file `src/app/(backoffice)/pdv/sale-receipt.tsx` (`'use client'`):
   - Props: `receipt: ReceiptData; onNewSale: () => void`
   - Renders a receipt card with:
     - **Header**: "Comprovante de Venda" title + `shortId` + formatted date (`toLocaleDateString('pt-BR', { ... hour: '2-digit', minute: '2-digit' })`)
     - **Customer row**: rendered only when `receipt.customerName` is non-null: `Cliente: {name}`
     - **Items table** (`<table>`): columns Produto, Qtd, Unitário, Subtotal — one row per item showing `productName` + `frameColor/lensColor`, quantity, `unitPrice`, `subtotal` — all amounts formatted as `R$ X,XX`
     - **Total row**: bold separator line + `Total: R$ {totalAmount}` right-aligned
     - **Payment breakdown**: list of non-zero payment methods with labels (`Pix`, `Cartão Crédito`, `Cartão Débito`, `Dinheiro`) and amounts; label `Troca` for `exchange` key
     - **Action buttons** (hidden on print via `print:hidden`):
       - "Imprimir" (`<Button>`) — calls `window.print()`
       - "Nova Venda" (`<Button variant="outline">`) — calls `onNewSale()`
   - The receipt card itself uses `print:block` and `print:shadow-none` so it prints cleanly; the buttons div uses `print:hidden`
   - (FR-3 AC-3.5, NFR-2)

6. **`pdv-client.tsx` integration** — modify `src/app/(backoffice)/pdv/pdv-client.tsx`:
   - Add state: `const [receipt, setReceipt] = useState<ReceiptData | null>(null)`
   - After `createSaleAction` succeeds:
     - Call `getSaleForReceiptAction(result.saleId)` to fetch `ReceiptData`
     - If success: set `receipt` state; clear cart; clear customer; clear `userEditedPayment`
     - If fetch fails: fall back to existing `successMessage` behaviour (no regression)
   - When `receipt !== null`: render `<SaleReceipt receipt={receipt} onNewSale={handleNewSale} />` **replacing** the right-panel cart/payment content (receipt takes over the panel)
   - `handleNewSale()`: clears `receipt`, clears cart, clears customer, clears `userEditedPayment` (same as existing `handleClearCart` + receipt clear)
   - Remove `successMessage` state — receipt replaces it (the success feedback is now the receipt itself)
   - (FR-3 AC-3.5)

7. **Print styles** — in `src/app/globals.css` (or via Tailwind `print:` variants inline), ensure:
   - On `@media print`: hide the sidebar, left product panel, and top nav; show only the receipt card
   - Use `print:hidden` on the left panel wrapper in `pdv-client.tsx` when `receipt !== null`
   - No external CSS file required — use Tailwind's `print:` variants exclusively
   - (FR-3 AC-3.5, NFR-2)

8. **Typecheck + lint** — `npx tsc --noEmit` and `npm run lint` must pass with zero errors; no new test file required for this story (receipt is a pure UI component; `buildReceipt` is a pure function tested implicitly via the existing sales service tests).
   - (FR-3 AC-3.5)

- **`window.print()`**: call directly in the `onClick` handler — no wrapper needed; works in modern browsers on PC and tablet (NFR-2 / ASM-5).

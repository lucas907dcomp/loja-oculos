## Story

**As a** store owner (single admin user),
**I want** a secure login page and a protected backoffice layout with sidebar navigation,
**so that** only I can access the backoffice system, and I can navigate to all major sections without friction.

## Acceptance Criteria

1. `src/lib/auth.ts` configures NextAuth.js v5 with a Credentials provider; admin identity validated against `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH` environment variables; password compared using `bcryptjs.compare()`.
2. NextAuth API route created at `app/api/auth/[...nextauth]/route.ts` (re-exports `handlers.GET` and `handlers.POST` from `src/lib/auth.ts`); session strategy set to `jwt` with TTL of 7 days (see spec.md Section 7 — risk: session expiry during sale).
3. Login page at `app/(auth)/login/page.tsx` renders a form with email and password fields; form uses react-hook-form + zod validation (email: valid format; password: min 8 chars).
4. Valid credentials redirect user to `/dashboard`; invalid credentials display an inline error message (e.g., "Email ou senha inválidos") without leaking internal error details.
5. `app/(backoffice)/layout.tsx` is an async Server Component that calls `auth()` from NextAuth; unauthenticated requests are redirected to `/login` via Next.js `redirect()` before any backoffice content is rendered.
6. Backoffice layout renders a sidebar with navigation links to all 8 main sections, in order: Dashboard, Produtos, Estoque, PDV, Vendas, Clientes, Fornecedores, Financeiro — paths match spec.md Section 3.2 route structure.
7. `.env.local.example` updated with two new keys: `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH`, each with a comment describing how to generate the value (password hash: `node -e "require('bcryptjs').hash('yourpassword', 12).then(console.log)"`).
8. `src/features/auth/auth.contract.ts` exports the `SessionUser` type and any auth-related type contracts used by other features.
9. Root `app/layout.tsx` wraps `{children}` with `SessionProvider` from `next-auth/react` to enable client-side session hooks.
10. `npm run dev` starts without errors; `npx tsc --noEmit` and `npm run lint` pass clean; login page renders correctly in the browser.

### NextAuth.js v5 — App Router Pattern
[Source: spec.md#section-3-1 — "Auth: NextAuth.js v5 — Credentials provider; sessão JWT httpOnly; 1 perfil (ASM-1)"]

NextAuth v5 (Auth.js) changes the API from v4. The correct pattern for Next.js 16 App Router:

```typescript
// src/lib/auth.ts
import NextAuth from 'next-auth'
import Credentials from 'next-auth/providers/credentials'
import bcrypt from 'bcryptjs'

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    Credentials({
      credentials: {
        email: { label: 'Email', type: 'email' },
        password: { label: 'Senha', type: 'password' },
      },
      async authorize(credentials) {
        const email = credentials?.email as string
        const password = credentials?.password as string
        if (!email || !password) return null
        if (email !== process.env.ADMIN_EMAIL) return null
        const hash = process.env.ADMIN_PASSWORD_HASH
        if (!hash) return null
        const valid = await bcrypt.compare(password, hash)
        if (!valid) return null
        return { id: 'admin', email }
      },
    }),
  ],
  session: { strategy: 'jwt', maxAge: 7 * 24 * 60 * 60 },
  pages: { signIn: '/login' },
})
```

**Key v5 differences from v4:**
- `getServerSession()` is GONE — use `const session = await auth()` in Server Components
- `handlers.GET` / `handlers.POST` are re-exported to the `[...nextauth]` route
- `signIn` / `signOut` are now importable from `@/lib/auth` for server-side use, and from `next-auth/react` for client-side use
- `AUTH_SECRET` env var (not `NEXTAUTH_SECRET` — Auth.js v5 renamed this)

### Route Protection Pattern
[Source: spec.md#section-5-2 — "(backoffice)/layout.tsx — Auth guard + sidebar"]

```typescript
// app/(backoffice)/layout.tsx
import { auth } from '@/lib/auth'
import { redirect } from 'next/navigation'

export default async function BackofficeLayout({ children }: { children: React.ReactNode }) {
  const session = await auth()
  if (!session) redirect('/login')

  return (
    <div className="flex h-screen">
      <Sidebar />
      <main className="flex-1 overflow-auto p-6">{children}</main>
    </div>
  )
}
```

**Why server-side redirect:** Client-side redirects flash unprotected content before redirecting. Server-side `redirect()` in the layout prevents any RSC from rendering for unauthenticated requests.

### SessionProvider — Client Boundary
[Source: Next.js 16 App Router pattern for NextAuth v5]

Root layout must be a Server Component (for performance). `SessionProvider` is a Client Component. Pattern to avoid marking root layout as `'use client'`:

```typescript
// src/components/providers.tsx
'use client'
import { SessionProvider } from 'next-auth/react'

export function Providers({ children }: { children: React.ReactNode }) {
  return <SessionProvider>{children}</SessionProvider>
}
```

```typescript
// app/layout.tsx  (remains Server Component)
import { Providers } from '@/components/providers'

export default function RootLayout({ children }) {
  return (
    <html lang="pt-BR">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  )
}
```

### Password Generation (for development)
[Source: spec.md#section-3-1 — ASM-1 single admin user]

To generate `ADMIN_PASSWORD_HASH` for `.env`:

```bash
node -e "require('bcryptjs').hash('yourpassword', 12).then(console.log)"
```

Copy the output (a `$2b$12$...` string) into `.env` as `ADMIN_PASSWORD_HASH`.

**Cost factor 12** is appropriate for a server-side check on a single admin login. Higher cost would slow down normal bcrypt brute-force attempts without meaningfully impacting the single legitimate user.

### Session TTL — 7 Days
[Source: spec.md#section-7 — "Sessão JWT expirar no meio de uma venda — Baixa / Médio — Configurar session TTL longo (ex: 7 dias); renovação silenciosa com NextAuth"]

`maxAge: 7 * 24 * 60 * 60` in `session` config. NextAuth v5 automatically refreshes the JWT on each request when `updateAge` is not set to `0`. This prevents the session from expiring during a long PDV session.

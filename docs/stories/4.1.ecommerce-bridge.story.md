## Story

**As a** store owner,
**I want** to expose product catalog, inventory, and customer data via a secured REST API,
**so that** a future e-commerce platform can sync products, check live stock, and import customers without requiring a full system rewrite (spec.md Sections 3.5, 5.5, FR-12, CON-2, CON-5).

## Acceptance Criteria

1. **Middleware auth (CON-5)** — `src/middleware.ts` is created:
   - Reads the `x-api-key` header from the incoming request
   - Compares against `process.env.ECOMMERCE_API_KEY`
   - Returns `HTTP 401` + `{"error": "Missing or invalid API key"}` when header is absent or does not match
   - Calls `NextResponse.next()` when key is valid
   - `config.matcher` is `'/api/v1/:path*'` — does NOT intercept backoffice routes
   - (CON-5)

2. **ExportService contract** — `src/features/export/export.contract.ts` exports:
   - `ExportFilters` type: `{ supplierId?: string; brand?: string; includeArchived?: boolean }`
   - `ExportVariant` type: `{ id: string; sku: string; frameColor: string; lensColor: string; uvProtection: string; isPolarized: boolean; price: string; stock: number; images: string[] }`
     - `price` is a string (preserves Decimal precision, e.g. `"199.90"`)
     - `stock` is the current inventory quantity (`0` when no Inventory row exists)
   - `ExportProduct` type: `{ id: string; name: string; brand: string; description: string | null; supplierId: string | null; variants: ExportVariant[] }`
   - Barrel-exported from `src/features/export/index.ts` alongside `ExportService`
   - (FR-12, CON-2)

3. **ExportService JSON** — `src/features/export/services/export.service.ts`, static class:
   - `exportCatalogJson(filters?: ExportFilters): Promise<string>`
     - Queries `product.findMany` with `include: { variants: { include: { inventory: true } } }`
     - Default: `isArchived: false` (archived excluded unless `filters.includeArchived === true`)
     - Maps each product to `ExportProduct`; `price = v.salePrice.toString()`; `stock = v.inventory?.quantity ?? 0`
     - Returns `JSON.stringify(products, null, 2)`
   - (FR-12 AC-12.1, AC-12.2)

4. **ExportService CSV** — same class:
   - `exportCatalogCsv(filters?: ExportFilters): Promise<string>`
   - CSV headers (in order): `product_id,product_name,brand,description,variant_id,sku,frame_color,lens_color,uv_protection,is_polarized,price,stock,images`
   - One row per variant; `images` is a pipe-separated list of URLs (e.g. `url1|url2`); empty string when `[]`
   - Returns CSV as a single string with `\n` line endings
   - (FR-12 AC-12.2)

5. **ExportService filters (AC-12.3)** — applied in both `exportCatalogJson` and `exportCatalogCsv`:
   - `filters.supplierId` → adds `where: { supplierId }` to the Prisma query
   - `filters.brand` → adds `where: { brand }` to the Prisma query
   - `filters.includeArchived` → when `true`, omits the `isArchived: false` guard (returns all); when `false`/absent, only non-archived
   - Filters compose with `AND` (supplierId AND brand AND status all apply simultaneously)
   - (FR-12 AC-12.3)

6. **GET /api/v1/products route** — `src/app/api/v1/products/route.ts`:
   - Accepts optional query params: `?format=json|csv` (default: `json`), `?supplierId=`, `?brand=`, `?includeArchived=true`
   - `format=json`: calls `ExportService.exportCatalogJson(filters)`, returns `Response` with `Content-Type: application/json`
   - `format=csv`: calls `ExportService.exportCatalogCsv(filters)`, returns `Response` with `Content-Type: text/csv` and `Content-Disposition: attachment; filename="catalog.csv"`
   - On service error: returns `HTTP 500` + `{"error": "Failed to export catalog"}`
   - (FR-12, CON-2)

7. **GET /api/v1/inventory route** — `src/app/api/v1/inventory/route.ts`:
   - Returns JSON array of stock levels for all non-archived product variants
   - Each entry: `{ variantId: string; sku: string; productName: string; quantity: number; minStockAlert: number; isLowStock: boolean }`
     - `isLowStock = quantity <= minStockAlert`
     - `quantity = 0` and `minStockAlert = 3` when no Inventory row exists
   - Query: `productVariant.findMany` where `product.isArchived = false`, includes `product`, `inventory`
   - Returns `Response` with `Content-Type: application/json`
   - (CON-2)

8. **GET/POST /api/v1/customers route** — `src/app/api/v1/customers/route.ts`:
   - `GET /api/v1/customers`: returns JSON array of all customers, each as `{ id, name, phone, email, tags, createdAt }`; ordered by `createdAt DESC`
   - `POST /api/v1/customers`: parses JSON body in a try/catch — returns `HTTP 400` + `{"error": "Invalid JSON body"}` if `request.json()` throws; requires `name` (string, non-empty); accepts `phone?`, `email?`, `tags?: string[]`; calls `prisma.customer.create`; returns `HTTP 201` + created customer JSON; returns `HTTP 400` + `{"error": "name is required"}` when `name` is missing/empty
   - (CON-2)

9. **Unit tests** — `src/features/export/__tests__/export.service.test.ts` (new file):
   - Mock `prisma` with `vi.hoisted` pattern (same as `sales.service.test.ts`)
   - `exportCatalogJson` — happy path: returns valid JSON string; parsed output has correct `ExportProduct` shape; `price` is a string; `stock` reflects inventory quantity
   - `exportCatalogJson` — archived excluded by default: archived products not in result
   - `exportCatalogJson` — `includeArchived: true`: includes archived products
   - `exportCatalogJson` — `supplierId` filter: Prisma called with `where: { supplierId }`
   - `exportCatalogCsv` — returns string starting with correct CSV header row; each variant is a row; `is_polarized` is `"true"` or `"false"`
   - (FR-12)

### Middleware Implementation (CON-5)

[Source: spec.md Section 3.5 — exact code provided]

```typescript
// src/middleware.ts
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  const apiKey = request.headers.get('x-api-key')
  const expectedKey = process.env.ECOMMERCE_API_KEY

  if (!expectedKey || apiKey !== expectedKey) {
    return NextResponse.json(
      { error: 'Missing or invalid API key' },
      { status: 401 }
    )
  }
  return NextResponse.next()
}

export const config = {
  matcher: '/api/v1/:path*',
}
```

**Critical:** `!expectedKey` guard means if the env var is not set, ALL requests to `/api/v1/*` return 401. This is intentional — an unconfigured key should fail closed, not open.

**Non-interference:** `matcher: '/api/v1/:path*'` does NOT match `/api/auth/*` (NextAuth) or any backoffice page routes.

### ExportService — Decimal Handling

[Source: spec.md Section 3.5 — CON-5 pattern; src/features/sales/services/sales.service.ts — Decimal usage]

`salePrice` is a Prisma `Decimal` field (`Decimal(10,2)`). The export contract uses `price: string` to preserve precision and avoid floating-point rounding. Convert with:

```typescript
price: v.salePrice.toString()   // "199.90" — exact string from Decimal
```

**NEVER** use `Number(v.salePrice)` or `parseFloat(...)` for the export price — this matches the pattern used in `LabelService` (AC-10.1 note on Decimal) and the general monetary field rule in this project.

### ExportService — Filter Composition

[Source: requirements.json FR-12 AC-12.3]

Build the Prisma `where` clause from optional filters:

```typescript
const where: Prisma.ProductWhereInput = {
  ...(filters?.includeArchived !== true && { isArchived: false }),
  ...(filters?.supplierId && { supplierId: filters.supplierId }),
  ...(filters?.brand && { brand: filters.brand }),
}
```

Note: there is no `category` model in the schema. `brand` is used as the category proxy for FR-12 AC-12.3 ("filtros por categoria") — this is the only category-like field available in the MVP schema.

### API Route Pattern

[Source: Next.js App Router convention; no existing `/api/v1/` routes in this project]

API route handlers live in `src/app/api/v1/` (NOT `app/api/v1/` — the project uses `src/app/` as the app root based on existing `src/app/(backoffice)/` convention).

```typescript
// src/app/api/v1/products/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { ExportService } from '@/features/export'

export async function GET(request: NextRequest) {
  const { searchParams } = request.nextUrl
  const format = searchParams.get('format') ?? 'json'
  const filters = {
    supplierId: searchParams.get('supplierId') ?? undefined,
    brand: searchParams.get('brand') ?? undefined,
    includeArchived: searchParams.get('includeArchived') === 'true',
  }

  try {
    if (format === 'csv') {
      const csv = await ExportService.exportCatalogCsv(filters)
      return new Response(csv, {
        headers: {
          'Content-Type': 'text/csv',
          'Content-Disposition': 'attachment; filename="catalog.csv"',
        },
      })
    }
    const json = await ExportService.exportCatalogJson(filters)
    return new Response(json, { headers: { 'Content-Type': 'application/json' } })
  } catch {
    return NextResponse.json({ error: 'Failed to export catalog' }, { status: 500 })
  }
}
```

### Inventory Route — Null Safety

[Source: prisma/schema.prisma — Inventory has `@unique` on variantId but is optional (ProductVariant.inventory is `Inventory?`)]

Some product variants may not have an Inventory row if created outside the normal flow. Guard:

```typescript
quantity: v.inventory?.quantity ?? 0,
minStockAlert: v.inventory?.minStockAlert ?? 3,
isLowStock: (v.inventory?.quantity ?? 0) <= (v.inventory?.minStockAlert ?? 3),
```

### POST /api/v1/customers — Body Parsing

[Source: Next.js App Router convention]

```typescript
export async function POST(request: NextRequest) {
  const body = await request.json()
  if (!body.name || typeof body.name !== 'string' || body.name.trim() === '') {
    return NextResponse.json({ error: 'name is required' }, { status: 400 })
  }
  const customer = await prisma.customer.create({
    data: {
      name: body.name.trim(),
      phone: body.phone ?? null,
      email: body.email ?? null,
      tags: Array.isArray(body.tags) ? body.tags : [],
    },
  })
  return NextResponse.json(customer, { status: 201 })
}
```

### CSV Header Order & Format Note

[Source: FR-12 AC-12.1, AC-12.2 — must include all required fields]

```
product_id,product_name,brand,description,variant_id,sku,frame_color,lens_color,uv_protection,is_polarized,price,stock,images
```

`images` is pipe-separated (`url1|url2|url3`); empty string when `images = []`. This prevents commas inside the images column from breaking CSV parsing.

**Important**: This CSV schema is a **structured intermediate export format** — it is NOT a direct WooCommerce or Shopify native import file. The column names are descriptive and cover all required data fields (AC-12.1). A mapping/transform step would be required to convert this export into platform-specific import formats (e.g., WooCommerce product CSV with `post_title`, `regular_price`, etc.). This is acceptable for MVP per AC-12.2 ("compatível com schemas de e-commerce" means structurally compatible, not identical).

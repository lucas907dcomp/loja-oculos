## Story

**As a** store owner,
**I want** to register sunglasses products with composed variants (frame color, lens color, UV protection, polarized flag), automatically calculated gross margin, and a searchable product list,
**so that** I can precisely track which SKUs I carry, see real-time profitability per variant, and make better purchasing decisions (spec.md Section 1.1, FR-1 rationale, FR-4 rationale).

## Acceptance Criteria

1. `src/features/products/products.contract.ts` exports types `ProductWithVariants`, `VariantWithInventory`, `CreateProductDTO`, `CreateVariantDTO`, `UpdateProductDTO`; all monetary fields (`costPrice`, `salePrice`) typed as `Decimal` (from `decimal.js`) — never `number` (spec.md Section 3.1 — Rationale financeiro crítico); barrel-exported from `src/features/products/index.ts`.

2. `src/features/products/repositories/products.repository.ts` exports `ProductsRepository` with: `findAll({ includeArchived? })`, `findById(id)`, `create(dto)`, `archive(id)` — `create()` wraps product + variant + one `Inventory` per variant (`quantity=0`, `minStockAlert=3`) in a single `prisma.$transaction()`; `archive()` sets `isArchived=true` (soft delete only — physical DELETE is permanently blocked per EC-4).

3. `src/features/products/services/products.service.ts` exports `ProductsService` with: `generateSKU(productName, variant)` — produces uppercase SKU from initials of product name + variant attributes, e.g. `RAY-PRET-CINZ-UV400-P`; appends `-2`, `-3` suffix if generated SKU already exists in DB; `createProduct(dto)` validates at least 1 variant before calling repository; `archiveProduct(id)` delegates to repository `archive()`.

4. `calculateMargin` is NOT re-implemented — `products.service.ts` imports and re-exports it from `src/lib/decimal.ts` (already implemented in Story 1.1, AC-1.5). Formula: `(salePrice - costPrice) / salePrice * 100` using `Decimal.js`. (FR-4 AC-4.3)

5. `/produtos` page (`src/app/(backoffice)/produtos/page.tsx`) is an async Server Component that fetches the full product list server-side; renders a table with columns: Nome, Marca, Fornecedor, Variantes (count), Status; archived products filtered out by default; "Novo Produto" button links to `/produtos/novo`; each row links to `/produtos/[id]`.

6. `/produtos/novo` page (`src/app/(backoffice)/produtos/novo/`) — a multi-section form (Client Component) with: (a) product fields: nome (required), marca (required), descrição, fornecedor (optional select from Supplier list); (b) variant builder: add N variants each with frameColor, lensColor, uvProtection (`UV380`|`UV400`|`UV420`), isPolarized toggle, costPrice, salePrice; margin (%) shown live below each variant's price fields using `Decimal.js` (FR-4 AC-4.3); at least 1 variant required; EC-3 — zero costPrice is allowed but displays warning inline: "Margem não calculável — adicione o custo de aquisição"; form validated with react-hook-form + zod; on success redirects to `/produtos/[id]`.

7. `/produtos/[id]` page (`src/app/(backoffice)/produtos/[id]/page.tsx`) is an async Server Component showing: product header (name, brand, description, supplier, status badge); variant grid with columns: SKU, Cor Armação, Cor Lente, UV, Polarizado, Custo, Preço Venda, Margem %, Estoque (from `Inventory.quantity`); EC-4 — active product shows "Arquivar" button; archived product shows "Restaurar" button; physical delete button is absent entirely.

8. Image fields: `images` accepted as an array of URL strings per variant (up to 5); UI renders a simple text input per URL entry; no file upload implementation in this story (full image upload deferred per spec — story scoped to URL-based images).

9. Unit tests in `src/features/products/__tests__/products.service.test.ts`: (a) `generateSKU()` — expected format, uppercase, correct attribute segments; (b) `calculateMargin()` from `src/lib/decimal.ts` — precision test: `salePrice=150.00, costPrice=50.00 → 66.67%`; no floating-point error; (c) `createProduct()` — throws when called with zero variants; (d) `archiveProduct()` — marks product archived (mock repository).

10. `npx tsc --noEmit`, `npm run lint`, and all existing tests pass; `npm run dev` starts without errors.

**Critical:** `costPrice` and `salePrice` are `Decimal` in Prisma. When reading from Prisma in TypeScript, they arrive as `Prisma.Decimal`. Use `new Decimal(variant.costPrice.toString())` to convert to `decimal.js Decimal` before calculation.

### Margin Calculation
[Source: spec.md#section-3-1 — Rationale financeiro crítico; FR-4 AC-4.3; requirements.json FR-4]

```typescript
// src/lib/decimal.ts (Story 1.1 — REUSE this)
import Decimal from 'decimal.js'

export function calculateMargin(salePrice: Decimal, costPrice: Decimal): Decimal {
  if (salePrice.isZero()) return new Decimal(0)
  return salePrice.minus(costPrice).dividedBy(salePrice).times(100)
}
// Formula: (PV - CA) / PV * 100
// Test: salePrice=150, costPrice=50 → 66.666...% (not 66.66666666666666667 — Decimal precision)
```

In the Client Component, for live display, convert Decimal to string with `.toFixed(2)`:
```typescript
const margin = calculateMargin(new Decimal(salePriceStr || 0), new Decimal(costPriceStr || 0))
const marginDisplay = margin.toFixed(2) // "66.67"
```
Never store margin in state — always derive from costPrice/salePrice.

### SKU Generation
[Source: spec.md#section-3-4 — ProductVariant.sku; FR-1 AC-1.3]

SKU must be unique per variant. Suggested format:
```
{PROD_PREFIX}-{FRAME_SHORT}-{LENS_SHORT}-{UV}-{POL}
// Example: RAY-PRET-CINZ-UV400-P (polarized)
//          RAY-PRET-CINZ-UV400   (not polarized)
```

Implementation hints:
- Product prefix: first 3 uppercase chars of product name, e.g. "Ray-Ban" → "RAY"
- Color short: first 4 uppercase chars, "Preto" → "PRET", "Cinza" → "CINZ"
- UV: exact value, e.g., "UV400"
- Polarized: append "-P" if `isPolarized=true`
- Collision handling: check `prisma.productVariant.findUnique({ where: { sku } })` before saving; if exists, append `-2`, `-3`, etc.

### Atomic Create Transaction
[Source: spec.md#section-3-3 — prisma.$transaction; NFR-3]

```typescript
// ProductsRepository.create() pattern:
async create(dto: CreateProductDTO) {
  return prisma.$transaction(async (tx) => {
    const product = await tx.product.create({ data: { name, brand, ... } })
    for (const variantDto of dto.variants) {
      const variant = await tx.productVariant.create({
        data: { ...variantDto, sku: generatedSku, productId: product.id }
      })
      await tx.inventory.create({
        data: { variantId: variant.id, quantity: 0, minStockAlert: 3 }
      })
    }
    return product
  })
}
```

import Decimal from 'decimal.js'

export interface ProductWithVariants {
  id: string
  name: string
  brand: string

  isArchived: boolean
  supplierId: string | null

  sku: string
  frameColor: string
  lensColor: string
  uvProtection: string
  isPolarized: boolean
  costPrice: Decimal        // decimal.js, NOT Prisma.Decimal
  salePrice: Decimal        // decimal.js, NOT Prisma.Decimal

    minStockAlert: number

### Server Actions Pattern
[Source: Next.js 16 App Router — Server Actions; spec.md#section-3-2]

'use server'
import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { ProductsService } from './services/products.service'

export async function createProductAction(dto: CreateProductDTO) {
  const product = await ProductsService.createProduct(dto)
  revalidatePath('/produtos')
  redirect(`/produtos/${product.id}`)

  await ProductsService.archiveProduct(id)

### Prisma Decimal Conversion
[Source: spec.md#section-3-1 — Rationale financeiro crítico]

Prisma returns `Prisma.Decimal` objects (which have `.toString()` and `.toNumber()` methods). Convert to `decimal.js Decimal` before arithmetic:
```typescript
import Decimal from 'decimal.js'
// In repository, after Prisma query:
const cost = new Decimal(variant.costPrice.toString())
const sale = new Decimal(variant.salePrice.toString())
```
In the contract types, always use `decimal.js Decimal`, never `Prisma.Decimal` or `number`.
